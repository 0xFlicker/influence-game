# Frozen retrospective context and speaker order

RT-02 implements deterministic context compilers in [influence-retrospective.ts](../packages/engine/src/influence-retrospective.ts) and [werewolf/retrospective.ts](../packages/engine/src/werewolf/retrospective.ts). [retrospective-context.ts](../packages/engine/src/retrospective-context.ts) freezes their inputs, admits the complete context against model budgets and materializes the next speaker's input. The [contract](game-retrospective-contract.md) and [task plan](plans/2026-10-10-004-feat-game-retrospectives-implementation-plan.md) define the surrounding lifecycle. These helpers do not invoke providers or connect the current runners to the retrospective.

## Canonical account and dialogue

Both compilers first replay their own validated event history, find the original outcome source, and compile only that event prefix. Every event gets an explicitly numbered account entry; consecutive entries in the same round/day and phase form a contiguous section. Quiet phases, passes, skipped huddles, ballot forfeitures, ties, no-kill/no-elimination results and final outcomes remain visible. Werewolf's account reveals the original roles and resolved night choices after the outcome, including doctor saves, failed pack agreement and dead faction winners. No gameplay randomness or state changes while compiling.

Facts are rendered from an exhaustive typed allowlist. Original dialogue is a separate untrusted lane; the compiler does not interpret promises, allegations, alliances or role claims from speech. Recorded alliance terms and typed huddle communications also stay in that lane rather than becoming proof that the actor fulfilled a commitment. Production operations, private coordination diagnostics, schedule rationale, session authorization snapshots, cognition and provider internals are omitted. Influence's sealed format ballots disclose participation, not individual choices; the accepted aggregate and tiebreaker still explain the result.

Each quote has a canonical `eventSequence` anchor, a distinct `source` kind/sequence, actor, original scope, audience and exact text. Public audience is `[]`; `null` explicitly means the canonical source does not disclose an audience. Recorded contestant speech in public, Mingle, huddles, whispers and the Werewolf pack is included for this postgame account. Diary/thinking/system entries and native reasoning are excluded. This disclosure happens only in the private postgame model context; it does not change watch/MCP permissions or gameplay observations.

Werewolf speech is sourced directly from `werewolf.action_accepted`. Influence's ordinary speech is sourced from the complete captured product-dialogue prefix. The owning durable turn supplies `transcriptThroughSequence` at the original outcome and a canonical boundary anchor for every eligible product speech. Those are independent sequence spaces: the compiler never compares a transcript number to an event number, guesses speaker identity from a display name, or reconstructs the relation from prose. Missing, duplicate, future or reversed anchors fail clearly. RT-04 must obtain these relations from committed turn boundaries; an arbitrary current transcript read head is insufficient.

Exact canonical formal-speech pointers/correlation keys remove duplicate transcript representations. Correlated speaker/text/scope must match exactly; disagreement fails rather than hiding source drift. Text similarity is not correlation. Without such an exact link, distinct captured sources remain distinct. Quotes are ordered by their canonical anchors, preserving source-local sequence order and putting canonical quotes before transcript quotes at an equal anchor; the anchor identifies an owning boundary, not a fabricated finer-grained cross-stream clock.

The unshipped v1 input contract is refined to require source/scope/audience on dialogue. There is no decoder for the previous incomplete shape, migration/backfill or historical generation. Existing SQL stores this JSON shape without a schema change. New compilers reject obsolete roster/format/huddle contracts rather than introducing compatibility rendering.

## Frozen original characters and order

Influence uses canonical `player.eliminated` order, then remaining nonwinning finalists in original seat order, then the canonical winner. Tied finale results do not change the original seat order. A one-survivor format ending uses that survivor as winner; it does not require a jury finale.

Werewolf uses canonical night/day death order, followed by a survivor permutation generated with a local RNG and the semantic purpose `retrospective-survivors.v1`. The seed hashes the original game seed, game ID and outcome digest. The resulting complete permutation is stored in the canonical definition; the raw seed is absent from the dossier and speaker context. Recompiling after a committed start must match and reuse that definition exactly. Source or order drift is an error.

Original seat IDs/names and game-specific character/strategy snapshots are required. Influence explicitly accepts `influenceStrategy`; Werewolf uses its own recorded setup strategy. Editable current Agent Profiles are not a source. Frozen copies isolate the compiler result from later input mutations. `materializeRetrospectiveContext` supplies only the next speaker's own character/strategy, the whole original account (including everything after their exit), and all earlier accepted speeches verbatim. It checks the frozen input/definition binding and never adds speculative or future statements.

## Capacity admission

`RetrospectiveCapacityPolicy` independently names all effective primary/fallback models from the sealed manifest and supplies a positive admitted `maxContextBytes` for each. A missing/extra/duplicate budget or absent policy fails with `RetrospectiveContextCapacityError` and reason `capacity_unavailable`. Catalog entries currently do not declare context-window limits; this layer does not invent model limits or treat the shared four-characters-per-token estimate as a hard admission guarantee.

The provider/runtime owner must derive each admitted byte ceiling from that model's supported window/tokenizer, after reserving the exact system prompt, native tool schema, output and any reasoning allowance. RT-03 must supply this policy when constructing the invocation. A conservative byte ceiling is an admission policy, not measured provider token usage. The shared canonical context serializer is used both for admission and the eventual model input.

Admission checks every original speaker against every effective model before any dispatch. It includes the complete dossier, that speaker's character, exact request/reference metadata and the worst-case size of all prior 2,000-code-point speeches. Six UTF-8 JSON bytes per speech code point cover even escaped controls; sequence metadata uses the largest legal width. It does not tokenize repeated placeholder text and mistake a compressible string for a worst case. Insufficient capacity fails with reason `context_capacity_exceeded`, actor/model IDs and required/admitted bytes. There is no context truncation, late-phase deletion or predecessor summarization.

The separate 256 KiB storage guard still applies to the input. The future transactional writer must also satisfy PostgreSQL's formatted JSON size constraint. Capacity checks produce no provider calls, editable strategy updates or additional storage/progress authority.

## Verification scope

Provider-free fixtures cover early exits, classic tied finale, a format ending with one survivor, all Werewolf result scenarios (including draws/no-elimination, saves, unavailable actions and dead winners), and a multi-day game. They verify every event/phase, order, deterministic hashes, committed-definition reuse, exact prior speeches, source validation, disclosure and typed capacity/storage failures. A PostgreSQL fixture round-trips a compiled input with exact Unicode/whitespace and source references while excluding cognition. Runtime continuation, provider invocation, MCP/replay/Studio/export and model-quality acceptance remain subsequent tasks.
