## Sources and behavior

Reusable profiles and frozen games require distinct inventories. An agent-owned
demand references the existing captured body hash (or its existing application-owned
image URL). Game demands retain the source used by playback. Influence membership
is relational; Werewolf membership comes from `werewolf.started`, independently of
lobby seats. The explicit nine-ID cohort includes both games' full frozen casts.
Both inventories deduplicate through the existing source-hash/recipe job constraint.

The CLI exposes inventory, bounded run, status and selected retry, with explicit
local/production targeting and hard-disabled staging. Production writes durable work
for the existing Batch dispatcher. Local inference uses the original capability-based
claim/source/upload contract and never sends database or bucket credentials to Docker.
Failures remain opt-in retries; a rerun cannot steal an active lease. New character
submissions also record optional body demands, inside a savepoint so derivative
failures cannot reject the character.

The [runbook](../../deployment/character-cutouts.md) contains exact preview, single
selection, remaining inventory, status and retry commands, plus deployment prerequisites.

## Real local Docker evidence

Evidence lives in [the run directory](evidence/cutout-backfill-2026-10-25/).
The existing image was `house-character-cutouts:local` (`b8d130d2f043`). Every inference
container was constrained to 2 CPU / 16 GiB, with memory+swap also 16 GiB. Live Docker
inspection confirmed `NanoCpus=2000000000`, `Memory=17179869184`,
`MemorySwap=17179869184`.

- Initial development inventory: **81 references, nine reusable example agents and
  nine games**. 70 references had ready jobs, three shared one pending source hash,
  and eight failed source inspection because local uploads were resolved from the
  wrong cwd. These eight were preview errors, not durable failed demands.
- Single selected game `19eb77c0-0249-4efb-881f-f9b0465b2a51`: eight references reached
  ready. Only job `5bb4f0c1-fe93-43e0-a74d-4d90876d098b` needed inference: **64.62 s**,
  peak cgroup **9,530,798,080 bytes**. Seven ready jobs were reused.
- Single-agent rerun reused the ready job without Docker. A first diagnostic run
  exposed unnecessary callback binding for ready work; the fixed runner binds only
  when it has a pending worker to launch.
- Remaining inventory ran first with limit 4, then resumed with limit 100. The final
  inventory reports **81 ready, zero selected, no remaining work**. Source bytes were
  not regenerated. Local upload resolution now defaults to the API's upload directory
  independently of the command's cwd.
- Interruption/failure tests used **`influence_cutout_proof_20261025`**, a separate local
  database containing copies of the nine existing profiles and their immutable image
  references. Development jobs and accepted game history were not reset.
- A one-second bounded wait stopped Docker for job
  `0c4cfd09-c961-415c-9ac9-0f435437b023` and exited 2, retaining its submitted lease.
  Immediate resume skipped that lease. After **simulated deadline passage in the
  isolated database only**, the same job completed on attempt two: **29.01 s**.
  This tests the recovery fence without waiting an hour or expiring live work.
- Three simulated abandoned dispatch deadlines made isolated job
  `3148c7ee-ea4e-46d6-a0e0-02ec286d6323` fail at the normal attempt limit. Explicit
  `retry --job` then completed through real Docker in **23.92 s**. No ordinary run
  reset the failure.
- Source retry uses an intentionally missing upload-directory override in the
  isolated database, then removes that override and retries exactly demand
  `e2b1532c-93a9-4100-81be-472f59368eb3`. See `isolated-source-failure.jsonl` and
  `explicit-source-retry.jsonl` for the durable failure and completion.

Earlier setup/diagnostic failures remain in the evidence directory under their
original filenames; successful reruns have new filenames. No successful evidence
was overwritten.
