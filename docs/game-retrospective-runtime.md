# Game retrospective runtime

## Editorial retakes on localhost

A Producer/Sysop can record a fresh statement for one contestant in a completed Werewolf game with a ready voice track. This is a presentation revision: the accepted event, original speech, provider evidence, outcome and later contestants' original contexts remain unchanged. The new request uses the original speaker's frozen game account and only the earlier canonical retrospective statements. It uses the selected model explicitly, the strict retrospective speech contract, and the shared primarily-English guidance.

Run `packages/api/src/scripts/retake-werewolf-retrospective.ts` with Bun and an explicit localhost `DATABASE_URL`, the normal private-storage/provider environment, and a current localhost Producer/Sysop CLI session:

```sh
bun packages/api/src/scripts/retake-werewolf-retrospective.ts preview GAME ACTOR
bun packages/api/src/scripts/retake-werewolf-retrospective.ts generate GAME ACTOR CATALOG_ID NEW_DIRECTORY
bun packages/api/src/scripts/retake-werewolf-retrospective.ts queue GAME NEW_DIRECTORY
bun packages/api/src/scripts/retake-werewolf-retrospective.ts run TRACK_ID
```

Generation requires a new private directory and durably journals provider attempts before continuing. Inspect `retake.json` before queueing. Queueing verifies the preview against the current source and active audio track, stores the context, statement and sanitized journal in private object storage, and creates a successor track with one pending clip. All other recordings reuse their verified immutable objects and original delivery recipes. PostgreSQL stores the source binding, document reference and publication metadata; migration `0136_retrospective_retakes.sql` must precede the new reader/writer deployment.

Text and audio publish in the same transaction only when the successor track is ready. A failed recording keeps the old presentation active and can be retried with `run TRACK_ID`. A pending or failed successor blocks another retake until it is resolved. Replay and Studio read the latest published retake at their publication cutoff; older pinned source reads retain their original speech. Revision provenance stays in metadata and is not added to the viewer caption. Canonical event and diagnostic reads still report the original statement. This command is local operator tooling; it does not add a regeneration MCP tool or change the planned moment-tagging MCP contract.

RT-04 connects Influence's existing runner to the [frozen context](game-retrospective-context.md) and [strict statement invocation](game-retrospective-invocation.md). RT-05 connects Werewolf to its own validated post-outcome stage, RT-06 makes its full completion proof the settlement boundary, and RT-07 exposes the canonical outcome while execution continues. Replay choreography, recovery and export work continue in the [implementation plan](plans/2026-10-10-004-feat-game-retrospectives-implementation-plan.md).

## Influence execution

Completed games without retrospectives are valid. Results and retrospective detail reads only require epilogue completion when canonical history actually entered `RETROSPECTIVE` or contains retrospective state, matching Production Studio. A completed game with no epilogue reports retrospective progress as `unavailable` with zero required statements; its canonical competitive outcome, replay and Studio remain available. This read policy does not weaken fresh-run settlement or accept a truncated retrospective. No history rewrite or generated historical speeches are needed.

Competitive wins enter a nonfinal `retrospective` machine state. Initialization measures the whole original roster against every sealed primary/fallback model for observability, compiles the original outcome account and commits `retrospective.started`. Each following durable turn plans one `retrospective-statement` subcall, accepts its strict speech, and atomically commits its canonical record, correlated public dialogue, publication, provider receipt and next ordinal. Eliminated contestants remain available as original agents; their gameplay eligibility does not change.

The completion turn validates the complete roster proof, commits `retrospective.completed`, enters END and creates the existing held completion publication. Neither the competitive result nor an intermediate speech creates that publication. The event bus remains available until the epilogue finishes. API settlement remains the caller's responsibility. RT-06 requires a validated complete event head, original outcome, all required statements, completion proof and END at terminal reconstruction, capture and pending settlement. An outcome alone cannot seal dialogue, release completion publication or trigger final effects.

Initialization stores the private dossier in `game_retrospective_inputs` inside the same owner-fenced transaction as its canonical definition. The writer validates the canonical source, game kind, definition hash and exact input binding; size does not reject initialization. A later failure rolls back both records. Resumption reads the immutable input and accepted prefix. Fresh statement dispatch always goes through the sealed manifest with normal retry/fallback traversal (no capacity admission gate), and accepted provider replay uses no transport.

Product dialogue and canonical events have independent sequence spaces. The API store captures the original outcome's owning committed turn and its dialogue head. Each original dialogue entry uses its persisted owning-turn event boundary, capped at the original outcome. Local runs bind dialogue at explicit completed phase boundaries; a supplied phase-boundary resume capsule binds its existing dialogue to that checkpoint. No current read head or transcript prose invents a source relationship. Formal speech writers now supply exact dialogue pointers; validation reuses their structured display formatter for presentation labels.

An exact round limit can stop an Influence evaluation before any competitive outcome exists. Such a bounded run has no retrospective and cannot provide the new competitive completion proof. Normal API runs retain their existing player-scaled completion floor. This does not manufacture a winner or draw for partial evaluations.

## Werewolf execution

Existing rules-v7 games retain their stored configuration, canonical history and original completion boundary at `werewolf.completed`. Replay, results and Production Studio continue to read and edit those games without a retrospective completion record. They do not enter retrospective generation or gain fabricated speeches. No migration or game-history rewrite is required. Fresh v8 games still require the complete retrospective proof.

Fresh games use rules v8. `werewolf.completed` freezes the competitive outcome and enters the retrospective phase. The same runner freezes the complete roster, atomically stores the private input with `werewolf.retrospective_started`, then prepares one exact request and full-context hash in `werewolf_turns` before each statement. The shared provider journal validates that slot under the current owner fence; accepted replay uses its existing value without another count or generation request.

Only retrospective events can follow the v8 outcome. Each statement adds a public speech entry with explicit retrospective purpose and ordinal. Dead speakers retain their original identity without changing the alive set, roles, opening cursor or earlier gameplay. The final full-roster proof closes the existing owner and catalog execution and queues the existing Cuts/media work. Outcome with an unfinished tail remains adoptable; required speech failure has no gameplay fallback. Completed production sources, trailers and learning input validate the version-specific finished-execution boundary, including v7 games without retrospectives. Previously frozen production prefixes retain their exact source boundary when the whole execution is complete.

## Local proof and remaining integration

Results availability follows the validated original outcome. Influence results schema v3 and Werewolf results schema v2 include `retrospective`: outcome source, pending/in-progress/completed status, accepted count, required original roster count and next actor. Influence watch state v6 carries the same progress and an available canonical winner before settlement. The independent cached list-card schema stays v4; it does not store statement detail. Invalid canonical history cannot claim a winner, and terminal database rows alone cannot supply canonical results.

House inspection and replay result links use the selected canonical prefix. A retrospective dialogue entry is joined to its accepted statement through the canonical transcript pointer, checked against its actor and verbatim text, and cannot advance past the fact lane. Mystery reads before Werewolf's outcome retain their earlier disclosure boundary. Current reads continue polling after the outcome while the catalog remains in progress. Only final settlement publishes completion and `game_over`; result pages refresh progress while execution continues.

Stopping after an accepted outcome pauses execution as `suspended`, revokes the active owner and preserves the outcome, event head and unset completion timestamp. It does not turn the game into a cancellation. Paused result pages retain the winner and accepted statement count. Stops before an outcome keep their existing cancellation behavior.

Required-step exhaustion is a typed `RetrospectiveExecutionError`, including structured/provider failure, circuit/spend exhaustion and invalid model configuration. In one owner-fenced transaction, the runtime stores a failure identity with the original outcome, current event head, definition/input hashes, planned actor/ordinal/request/logical call, reason code and owner epoch; it suspends the catalog and releases the owner. Influence retains its cursor as `repair_required`. Startup and legacy recovery exclude both these failures and explicit retrospective pauses. Cancellation and uncertain commit failures retain ordinary durable adoption semantics. The provider journal also bounds attempts for each retrospective model entry across owner changes. An exhausted entry cannot redispatch after a crash before suspension; remaining sealed fallbacks may proceed. If every entry is exhausted, the new owner checkpoints `journal_exhausted` without another generation call.

The shared recovery mutation compares the expected head and failure identity, validates the unchanged frozen input and cursor, checks deployment recovery admission, and records a bounded idempotency key before returning the game to the existing worker. Explicit recovery stores the existing attempt ordinal as the floor for a fresh bounded retry policy for this one logical slot. It never replaces accepted speeches, clears provider receipts, changes the sealed provider route or refunds fallback reservations. API sessions require a current admin/sysop/producer role plus `resume_game_retrospective` permission inside the mutation transaction. MCP also requires the separately consented `games:read games:resume` grant and client envelope. Producer diagnostics alone do not authorize generation. A repeated identical request reports the actual current status; a changed head, failure or request conflicts.

Retrospective dispatch remains active worker ownership during drain. Aborting a dispatched speech drains the runtime and releases its lease, preserving the committed frontier without recording a provider failure or fabricated speech. Accepted provider values still replay once locally after a response-to-event interruption. Remote outcomes whose response was never journaled can be billed twice on recovery; local exactly-once acceptance is not an exactly-once remote billing guarantee.

Creation records a roster-sized retrospective forecast and the model editor shows the added calls. Each original contestant needs one speech, with the existing two-attempt Influence or three-attempt Werewolf policy per model. Context includes the whole game plus growing verbatim priors; the forecast separately bounds accumulated escaped speech text, not the unknown full input cost. Fallback caps cover gameplay and the epilogue together and are never silently increased. Existing spend diagnostics group these receipts under `retrospective-statement`; final accounting includes their token usage and retained reservations.

Deterministic engine tests restart at outcome, initialization, every statement ordinal and final completion. They verify exact prior text, unchanged outcome/order, one speech per original contestant, no premature completion, correlated dialogue, and a required-speech failure retaining its unfinished frontier. Database proof exercises rollback after private-input insertion and successful restart into one complete epilogue.

Fresh local runner calls also execute the epilogue. Simulation artifacts retain explicit game identity, canonical events, the completed or failed frontier and compact provider usage/cost receipts. Local MCP uses separate Influence/Werewolf adapters and bounded public retrospective reads; API Werewolf reporting continues through the outcome and all final statements. Real statements dispatch on any sealed provider route, including Katana and local models. Paid/provider quality and deployed execution remain separately authorized validation.

Keep exact types without `as any`, separate private cognition from public speech, and call House methods directly. No extra worker, queue, speech fallback, media generation or historical generation is introduced.

## Replay presentation

The competitive result remains a readable cue before the Retrospective chapter. Each accepted speech uses the contestant's original solo portrait, name and canonical part/outcome. Influence clears its closing winner hold at this chapter; Werewolf reveals the original role and recorded exit/survival outcome in both audiences after the result. Existing clocks own pagination, pause, audio and seeking. A waiting/completed tail keeps the last speech readable. Mystery highlight discovery omits retrospective evidence so postgame knowledge cannot label earlier strategy; Omniscient retains the exact postgame chapter and source cursor.

## Studio source authority

Retrospective statements are ordinary selectable speech moments. Their purpose, actor, ordinal and canonical event sequence accompany the existing stable transcript/cursor identity. Influence's owning production reader verifies each captured row against its accepted statement, including exact text, actor, phase and event boundary; missing or substituted dialogue fails clearly. Werewolf uses its own validated post-result projection. Full sources require the completed retrospective proof. A validated visual pause can still preview its earlier accepted prefix, including an empty opening frontier, but cannot freeze a completed export.

Labels and recipes remain independent of semantic purpose. A retrospective-only cut contains exactly the selected speeches in source order; including the result is a separate choice. Source hashes include captured text and canonical provenance. The inspector shows the retrospective speaker ordinal and event reference without exposing the private dossier.
