# Season-linked championships and reusable awards

The implementation runs a separate event linked to its source season. Event games have `seasonId = null` and use the custom track: they do not enter the free queue or alter Season 0 scoring. Nothing is automatically activated by a migration, season finalization, roster lock, or publication.

## Qualification and frozen competition builds

Season finalization now commits a verified object-storage snapshot in the same transaction as honors and final status. It retains all receipts, scoring evidence carried by those receipts, the complete Agent and Architect rankings, qualification ranks and exact integer scores. New championship locks use that snapshot. Historical final seasons without a snapshot retain the legacy qualification reader; this compatibility path does not claim to reconstruct an original finalization snapshot. Season 0 is still open and will use the new path when explicitly finalized.

The field is the top eight agents, with multiple agents per owner allowed. Roster locking stores verified content-addressed competition builds, sealed model routes, both game strategies, source revision identity and frozen game configuration. Legacy missing revision pointers are repaired with the existing revision-maintenance helper before lock commits. Live-owner edits remain allowed, including while a championship game is waiting for a start retry. Ordinary seat projection cannot replace a competition build. Influence admission reconstructs the pinned roster and configuration at its atomic start boundary; Werewolf creates its canonical start event directly from the pinned build. Existing durable owner leases, provider journals and restart adoption run the accepted games.

The same eight play 16 Werewolf matches and one Influence finale. There are no automatic fillers or owner-consent requirements. Before lock, genuinely unavailable profiles are skipped in frozen standings order, with original rank and reason audited; the next available ranked agent enters. Availability is rechecked during preparation. Missing artwork and ordinary owner edits are not unavailability. After lock, no finalist is silently replaced. Cross-game memory remains deferred.

## Automatic finalist artwork

A lock request freezes each selected agent’s build inputs and enters `preparing`. Every finalist must have a verified headshot and full-body reference before the ledger locks. Existing artwork is copied into immutable verified storage; missing artwork is generated automatically, using the existing image as a character reference where available. If both are missing, the body is generated from the frozen character description and then used for the headshot. No agent-owner approval, click, or inference allowance is required.

The resulting competition revision retains the original agent/account and source revision links. Live profiles and existing assets remain unchanged. Frozen artwork hashes and content-addressed URLs are bound into every championship game’s build; subsequent owner edits cannot change them. The producer panel shows preparation progress and links to both images, and refreshes automatically while preparing.

A separate worker runs every 30 seconds. Leases, durable image payloads and the existing visual-provider journal preserve completed work across retries. Publication failure reuses generated bytes; known failed provider calls can retry automatically. Work is ordered so one failed finalist does not starve the others; each preparing event gets its own worker allowance. Retries reuse the saved request prompt and dimensions, verifying unchanged reference-image hashes even if the code template has changed. A genuinely uncertain provider response retains its receipt for producer reconciliation before another provider attempt; this is operational recovery, never owner consent or a monetary ceiling. Authorized operators inspect attempts and record reconciliation evidence through the API below. There is not yet a dedicated reconciliation form in the panel.

Migration 0149 adds preparation state and the account-linked artwork ledger. Inputs, headshots and bodies participate in the normal verified payload inventory. The worker automatically completes roster lock after all eight asset pairs are ready; it never activates the event.

## Schedule and recovery

All 17 schedule records are generated at midnight UTC from an explicit start date: Werewolf days 1–16, Influence day 17. The game-worker process checks due championship work every 30 seconds. Gateways do not run this loop. An optional narrowly authorized service wakeup calls the same reconciler; no separate AWS resource is required for the worker-based schedule.

Only explicitly activated events dispatch. Creation and dispatch lock the exact event/match identity; duplicate calls return the same game. They never select a newest waiting game. A crash after Influence game creation resumes its existing waiting game, and a crash after accepted start uses the normal durable worker adoption path. Existing deployment admission/maintenance fences remain in force. Temporary dispatch errors remain retryable and do not invalidate the field. Award and result-reconciliation failures do not prevent due gameplay dispatch. No monetary ceilings, reserves or spend-based stops were added.

The clock is a not-before boundary, not a promise of second-exact execution. Delayed starts catch up in scheduled order. Multiple overdue matches may overlap following an outage; accepted games retain independent durable leases. Activation/pause request identities are audited even for no-ops; delayed retries cannot reverse a later producer decision. Operators can explicitly pause future starts; that does not abort accepted games. There is no automatic cancellation after a game failure. Interrupted games recover their existing durable cursor. A cancelled attempt can be explicitly replayed from the producer panel with its exact game ID, a reason and an idempotency key; this preserves the abandoned game and its frozen membership, uses the same field/role lineup, and creates distinct seat identities. Delayed requests cannot replace a newer attempt. Crashes and cancellations receive no points and never become draws. Completed/scored matches use the separate audited result-correction operation described below.

## Balanced roles and spectator presentation

`balanced-roles-v1` generates two complete eight-rotation blocks, with exact per-agent role totals for the chosen role composition. A deterministic search prioritizes avoiding repeated complete lineups, then repeated wolf partners, then consecutive roles. New drafts prefill the confirmed composition: 2 wolves, 1 seer, 1 doctor and 4 villagers. Every agent therefore receives exactly 4 wolf, 2 seer, 2 doctor and 8 villager assignments across 16 games.

For each match, dispatch deterministically finds a private seed that reproduces its planned lineup under the existing Werewolf role-assignment function. The normal canonical reducer validates that assignment on start and replay; no alternate interpretation of released rules is introduced. Invalid role counts fail validation before seed selection.

Public views receive only unordered, opaque lineup IDs and role maps. Seeds, future match-to-lineup bindings, frozen strategies and private owner IDs are excluded. Roles use optional spoiler reveals. Late-series deduction is acknowledged. Contestant prompts and memory receive neither the collection of future lineups nor the private schedule. The event page links back to its season, shows scheduled/completed games, Werewolf points and wins, and the separate Influence champion.

## Results and awards

Settlement reads canonical Werewolf outcomes or the normal Influence completion receipt. Unique match/entry rows store one outcome and point award per contestant; transaction locking prevents duplicate counting. New drafts use the confirmed Season 0 policy: faction win 1 (including eliminated teammates), loss 0, genuine day-limit draw 0.5; rank by series points then exact frozen Season 0 score, sharing the championship when both tie. Existing event policies remain unchanged. Policy version `season-0-v2` supports exact half-point increments; migration 0147 widens historical integer scores without rescaling them or rewriting their version. Binary halves and every old int32 value are represented exactly. Shared winners each receive champion and architect awards. Influence's canonical winner wins its separate championship. An Influence draw remains unresolved pending a product decision; completed gameplay is retained rather than rerun automatically.

All 17 completed results finalize the event when winner resolution is complete. Finalization is audited. Result reconciliation and finalization also work while future dispatch is paused.

Built-in Season 0 badges cover Agent Crown, Architect Crown, season agent champion's architect, Top 8, Werewolf and Influence champions, each championship winner's architect, and agent/account participation. Additional reusable definitions support account or agent recipients. Public badge shelves appear on agent and account profiles.

Automatic allocation uses three independent phases: the locked field after activation, source-season honors/participation, and each game's championship. Each phase freezes recipient attribution and evidence in an object-backed outbox. Delivery retries preserve the allocation, use stable achievement/request keys, and never duplicate or implicitly reinstate a revoked badge. Participant counts use distinct completed game receipt identities, including otherwise ineligible scoring receipts; new drafts use the confirmed threshold of one completed Season 0 game for both agent and player/account participation. New drafts use the confirmed recorded-evidence attribution: Season 0 winners from finalization, championship identities/owners from the locked ledger, and participation from season receipts. Agents do not change hands; no transfer workflow is introduced. Existing configurable policies remain readable for historical events. A missing historical finalization snapshot defers automatic source-season allocation without blocking matches or other awards.

## Producer workflow and badge correction

`/admin/championships` is available to accounts with `manage_championships`. It lists up to 100 recent events and connects draft creation, explicit policy/date entry, top-eight roster lock, publication, activation/resume, pause, exact-match retry, and event-scoped reconciliation. Source-season operations remain in the existing Seasons screen; the championship panel never closes a season implicitly. Confirmed scoring, shared-champion fallback, role composition and one-game participation threshold are prefilled in new drafts; recorded-evidence attribution is also prefilled; dates remain undecided. A draft-create retry with the same slug/actor/source/name returns the same event; conflicting reuse is rejected.

Publication does not activate the schedule. Activation permits due games and automatic awards; overdue starts can overlap. Reconciliation from this panel targets only its selected event. Match rows show the actual game status when it differs from event progress, with links to existing game pages. Event audit history and operation receipts support recovery. Unknown browser operations retain their original request/body in the account-scoped admin session for a deliberate retry; this in-memory continuity does not survive a full browser reload.

Accounts with `manage_awards` can preview available allocations, including before activation after roster lock. Preview reuses the allocation planner without writing allocations, grants, or payload objects. Existing allocations are marked frozen/delivered; unallocated plans are explicitly previews and may change before allocation. Champion phases await canonical outcomes; source-season allocation needs finalization evidence. Event and source-season badges are listed together, with pagination.

Badge review exposes original evidence and its audit history only to authorized operators. Explicit revoke/reinstate actions require a reason, preserve the same grant identity and original evidence, and record every accepted correction. Delayed retries cannot reverse a later correction, including accepted no-ops. Automatic delivery still never reinstates a revoked badge. These visibility controls do not rewrite original recipients, evidence or canonical results. Separate result and recipient correction operations preserve those records as described below.

## Completed-result and recipient corrections

A producer with both `manage_championships` and `manage_awards` can correct an exact completed match using its current game ID, scoring revision, a reason and an idempotency key. **Resettle** recomputes from the existing canonical outcome under the frozen points policy; it does not execute a game. **Replay** explicitly requests another game with the same frozen field, artwork and role lineup, using distinct seats. Neither operation edits canonical games or previous score rows. There is no arbitrary winner/points override.

Every correction advances the match’s scoring revision. Standings count only rows bound to the current revision and game. Previous revisions remain in producer scoring history, with original game links and audit reasons. The affected Werewolf or Influence champion allocation is superseded; its grants and recipient-replacement descendants are revoked while their evidence remains intact. Field, participation, source-season awards and the other championship’s allocation remain unaffected. After canonical settlement, a new allocation generation delivers the current winners idempotently. Automatic delivery cannot revive superseded grants; explicit prior producer revocations remain withheld until deliberately reinstated.

Corrections serialize with settlement and award delivery using the event lock. Stale game/revision requests are rejected; repeating an accepted request is a no-op even after later corrections. Normal scheduled matches continue. An existing producer pause remains paused. Correcting a final event reopens it for the explicit correction; it finalizes again when all current results resolve, with a distinct finalization audit record. A replay from a paused event waits for explicit resume.

The producer panel exposes these two correction methods on completed match rows, requires a reason, and explains replay’s new-game effect. Its scoring-history section retains all derived revisions. Uncertain browser responses retain the original request identity for retry.

With `manage_awards`, a producer can replace a badge recipient using a valid account/agent ID matching the badge definition, a reason and explicit replacement evidence. This creates a linked replacement grant and revokes the original; the original recipient/evidence never changes. A replaced or superseded grant cannot be reinstated or corrected again as though it were current. Correct the current active replacement instead. This does not imply agents change ownership, alter qualification, or silently correct a related badge: each manually selected badge remains an explicit operation. Result-driven champion/architect updates are handled together by allocation recomputation.

Migration 0150 adds scoring revisions and game provenance, allocation generations/supersession and badge replacement/allocation links. It backfills historical identities without rewriting points, policy versions or evidence. Deploy the matching API/worker together before using correction controls.

## API and authority

Public reads: `GET /api/championships/:slug` (published only), `GET /api/award-definitions`, `GET /api/awards/agents/:id`, and `GET /api/awards/accounts/:publicIdentifier`.

`manage_championships` authorizes:

- `GET /api/admin/championships`: list recent events.
- `POST /api/admin/championships`: create or recover the same draft.
- `GET /api/admin/championships/:id`: inspect the event and unresolved policy choices.
- `PUT /api/admin/championships/:id`: configure draft policies and start date.
- `POST /api/admin/championships/:id/lock`: freeze qualification/builds/configuration, with `Idempotency-Key`.
- `GET /api/admin/championships/:id/artwork/:preparation/attempts`: inspect private provider receipts for this event and revision.
- `POST /api/admin/championships/:id/artwork/:preparation/attempts/:attempt/reconcile`: record producer evidence (`note`, `costMicrousd`) for an uncertain response; active leases and unrelated attempts are rejected.
- `POST /api/admin/championships/:id/publication`: change public visibility without activation.
- `POST /api/admin/championships/:id/activate`: explicit activation or resume, with `Idempotency-Key`.
- `POST /api/admin/championships/:id/pause`: pause future starts, with `Idempotency-Key`.
- `POST /api/admin/championships/:id/matches/:ordinal/dispatch`: retry one exact due match.
- `POST /api/admin/championships/:id/matches/:ordinal/replay`: replay a cancelled unscored attempt; requires `expectedGameId`, `reason` and `Idempotency-Key`. The worker can recover a crash between accepting replay and starting its new attempt.
- `POST /api/admin/championships/:id/matches/:ordinal/correct`: requires additional `manage_awards`, `expectedGameId`, `expectedRevision`, `mode` (`resettle` or `replay`), `reason` and `Idempotency-Key`.
- `POST /api/admin/championships/:id/reconcile`: reconcile only this event.
- `GET /api/admin/championships/:id/award-preview`: read-only allocation preview; also requires `manage_awards`.

`POST /api/internal/championships/reconcile` requires a service principal enabled in the database and a signed `dispatch_championship` scope, or a normally authenticated human with that permission. A free-queue-only token is insufficient. The route does not accept a caller-supplied clock or activation request.

`manage_awards` authorizes manual grants, revocations and explicit reinstatement with evidence/reason and `Idempotency-Key`. Producer reads use `GET /api/admin/awards?eventId=...&after=...` and `GET /api/admin/awards/:id`; reinstatement uses `POST /api/admin/awards/:id/reinstate`. Recipient/evidence replacement uses `POST /api/admin/awards/:id/correct-recipient` with `recipientType`, `recipientId`, `evidence`, `reason` and `Idempotency-Key`. `manage_award_definitions` authorizes custom definitions; built-in codes are reserved.

## Rollout and remaining decisions

Additive migrations 0145–0150 and payload inventory entries must deploy together with the API. After the renderer rebase and disposable upgrade proof, normal startup migrations were also applied to the existing local development database with explicit user authorization. No data reset, replacement or restore was performed. Bucket references are verified before commit; rolled-back uploads may leave content-addressed orphan objects for normal inventory/retention handling. Coordinate these additions with the separate AWS storage migration.

Do not activate a real event until its start date is chosen. An Influence draw policy also needs a product decision before a drawn finale can be finalized. Test values are fixtures, not production defaults.

Remaining policy/UI scope: arbitrary canonical-outcome adjudication, actual start date, hypothetical Influence-draw resolution, and any desired final badge-art refinement. Result corrections currently use canonical resettlement or explicit replay; they do not invent a different winner. In-player branding was not changed; existing viewer/Studio/export rendering remains the authority. The event page and profile award shelves are outside the player picture.

See `championship-validation.md` for exact local evidence and limits. No live provider execution or production activation is claimed.
