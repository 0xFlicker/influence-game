# Strict retrospective final statements

Mandatory `getRetrospectiveStatement` methods on `IAgent` / `InfluenceAgent` and `WerewolfAgent` / `WerewolfModelAgent` run through both existing engines and their durable API authorities. Simulations retain complete artifacts and bounded local MCP inspection. See the [runtime](game-retrospective-runtime.md), [contract](game-retrospective-contract.md), [context compiler](game-retrospective-context.md) and [task plan](plans/2026-10-10-004-feat-game-retrospectives-implementation-plan.md).

## Model contract and context

[retrospective-invocation.ts](../packages/engine/src/retrospective-invocation.ts) constructs a dedicated postgame prompt using the unchanged canonical context serialization: the complete original game account, the speaker's original persona/backstory/game-specific strategy and every earlier accepted speech verbatim. It snapshots and checks the request/input hash, actor and exact predecessor references before asynchronous work. Current memories, editable profiles, opponents' strategy/cognition and visual scene preparation do not enter the prompt. Influence's ordinary phase argument supplies execution metadata only.

The prompt asks for a candid 40–75 word reflection addressing the other contestants and the speaker's own performance, with at most 1,000 Unicode code points as prompt guidance. Characters may roast the game or each other and discuss mechanics openly. Canonical facts and untrusted quoted dialogue stay separate. A quote cannot instruct the model or establish that a promise was fulfilled. The native tool is exactly `submit_retrospective`, with the existing `{ speech: string }` artifact: nonblank, at most 2,000 Unicode code points, no extra fields. Accepted whitespace and Unicode remain unchanged. There is no pass, cue, private-thinking field, strategy delta or new gameplay action. The [paid trials](reviews/2026-10-11-game-retrospectives-model-quality.md) used the previous 80–150 word prompt and do not qualify this revision.

Both agents use `executeModelInvocation` and their existing coordinator and sealed provider manifest. Influence retains its configured structured-attempt limit (default two); Werewolf retains three attempts per entry. The coordinator alone owns retries, fallback traversal, cancellation, accounting and accepted-value replay. SDK retries are disabled. Exhaustion propagates a typed provider failure; no default speech is fabricated. RT-04/05/06 own representation and recovery of that failure.

The provider speech schema omits `pattern` for Katana compatibility. Local semantic validation rejects blank provider speech within the bounded retry/fallback loop and rejects blank accepted journal values. Canonical statement validation independently rejects blank speech during event ingestion and replay without changing the provider schema. Tool response decoding follows the compiled request format: Meta Responses uses native tool calls even when the global tool-choice setting is `json_schema`.

Influence retains its planned durable-turn/subcall coordinate when staged, or an explicit retrospective phase-call coordinate for standalone invocation. Werewolf retains its event action-slot coordinate. No provider-coordinate version or alternate journal is introduced. The staged inventory includes the method and bypasses scene generation, preserving existing art for later presentation work. Provider receipts account for every dispatched attempt; Influence's token tracker records newly accepted generation usage, including cached/reasoning tokens, without recounting replay.

## Dispatch without capacity admission

Retrospective always dispatches through the sealed manifest like every other invocation. There is no context-capacity admission gate: no token counting, no per-model window table, and no provider capability requirement. If a provider rejects an attempt — including a context-window overflow on a very long game — the coordinator's existing retry and fallback traversal moves to the next manifest entry, and only exhaustion of every entry surfaces as a typed provider failure for explicit recovery. `prepareRetrospectiveCapacityPolicy` now only assembles the frozen-context preflight policy shape with unbounded budgets (no network reads); the whole-roster preflight still serializes each speaker's worst-case context and records its byte size in receipts for observability, but never blocks initialization or dispatch. Accepted journal replay revalidates the artifact and supplied context without generating remotely.

This replaced the verified-admission design on 2026-10-13: requiring native token-count proof from every sealed entry suspended real games whose manifests carried Katana fallbacks, because the Katana router exposes no token-count or model-metadata endpoint to verify against. The account is still never truncated or summarized; an oversized prompt simply fails that attempt and falls back.
