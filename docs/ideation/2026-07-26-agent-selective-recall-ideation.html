Agent selective recall

Six grounded directions for letting The House’s agents remember strategically important history without turning transcript prose, a vector store, or a model tool call into a second source of game truth.

What is true today

Grounding Context

Authority is already split correctly

The Current Board Contract outranks Strategy Thread, assessments, and transcript prose. ContextBuilder already holds separate inputs for canonical events, revealed ledgers, actor-specific inboxes, recent decisions, and alliance context.

The actual growth paths are narrow

Ordinary prompts include current plus two prior public rounds, while endgame injects the complete public/system transcript. Mingle retains each delivered line for the phase and feeds full local turn history.

Privacy has a useful existing seam

Player-facing context filters private audiences, seals ballots, and excludes producer-only pointers and raw traces. Retrieval should reuse that policy, not query logs and attempt redaction afterward.

Continuity is structured, not raw memory

Strategy packets, accepted decision receipts, and checkpoint capsules deliberately exclude raw prompts, model responses, and reasoning. Their safe source locators are a better recall foundation than retrospective summaries.

Proof infrastructure exists

Deterministic tests, bounded operator simulations, accepted-action correlation, and structural prompt-reuse telemetry can test a policy without retaining its private prompt payload.

External prior art agrees on the order

Selective episodic memory can rank relevance, recency, and importance, but authorization must happen before ranking and retrieved text must be treated as untrusted evidence, not instructions or state.

1
Pinned game truth and typed exact recall

1. Recall Constitution

Description: Turn ContextBuilder into a deterministic policy compiler that emits a per-turn RecallPlan: the non-negotiable Board Contract, action-specific exact facts such as revealed ledgers and accepted receipts, then a strictly capped lane of conversational evidence. The planner—not a model, framework, or semantic index—decides which lane may answer each need. Semantic recall is an optional last rung for old authorized prose only.

Illustrative authority order: conversational recall can inform a decision without reconstructing the game board.

Axis
Pinned game truth and typed exact recall
Basis
direct: the existing Current Board Contract already overrides transcript and private strategy; ContextBuilder already separates canonical facts, ledgers, inboxes, and personal decisions. reasoned: consolidating that existing seam gives every current and future format one policy contract.
Rationale
This is the core move. It reduces prompt bloat without letting a retrieval result revive an eliminated player, re-open a sealed ballot, or repair an event gap with dialogue.
Downsides
High design discipline: each phase/action must declare its exact fact needs, and the first version should not promise semantic recall everywhere.

2
Actor-scoped conversation recall and privacy controls

2. Seal-Safe Recall Broker

Description: Put a server-owned recall broker between the plan and any transcript index. It binds gameId, actor, phase, and an allowed recall category before ranking; only public/system dialogue and that actor’s authorized deliveries can enter its candidate set. Audience partitions are created at write time, malformed/denied records fail closed, and inaccessible matches produce the same neutral non-result as no match.

Illustrative privacy boundary: the model never gets a whole-game search surface to negotiate with.

Axis
Actor-scoped conversation recall and privacy controls
Basis
direct: current private-lane reads are actor/ownership checked, malformed audiences fail closed, sealed identities remain absent, and source pointers/raw traces stay producer-only. external: authorization-before-retrieval and indirect prompt-injection guidance match this boundary.
Rationale
Every future ranker—literal, full text, or semantic—must use one sealed gate. That is far safer than trusting each new retrieval call site to remember visibility rules.
Downsides
Requires durable audience metadata and deliberate tests for existence side channels, not merely “no text leaked” assertions.

3
Context budgets, history growth, and selective ranking

3. Context Budget Auction

Description: Replace “two public rounds, then everything in endgame” with per-phase evidence-slot contracts. Board truth, action-critical exact receipts, and active-room conversation reserve their space; only the remaining slots are ranked by deterministic signals such as decision relevance, recency, unresolved claim linkage, and novelty. A structural selection receipt records lane, reason, count bucket, and token cost without storing retrieved payloads.

Axis
Context budgets, history growth, and selective ranking
Basis
direct: endgame currently renders full public/system history while other prompt surfaces and recent decisions are already bounded; prompt-reuse telemetry already classifies stable and volatile blocks without payload capture.
Rationale
The goal is not blind truncation. It prevents a long public argument from evicting a revealed vote or current Mingle exchange, while making cost and cache stability inspectable.
Downsides
Ranking weights are product policy and will be wrong initially; they need replay fixtures before they earn automatic trust.

4
Strategic continuity and recall provenance

4. Deliberate Social Memory

Description: Keep current-room Mingle exchange hot only for its active session. When an agent wants a social promise, accusation, or condition to survive automatically, it creates a compact audience-scoped social claim with original message coordinates, counterpart, condition, and expiry; otherwise the dialogue becomes cold evidence that must be deliberately recalled. The claim remains contestable social evidence, never canonical game state.

Axis
Strategic continuity and recall provenance
Basis
direct: Mingle delivery and recovery already have actor/phase boundaries, while structured alliance commitments are stored separately from transcript prose. reasoned: durable social play becomes more legible when agents intentionally carry a claim rather than hoping an old sentence ranks first.
Rationale
It retains the watchable part of social memory—“you promised X, subject to Y”—while reducing long-lived raw private context and keeping promises disputeable.
Downsides
It is a product mechanic as much as a context feature; careless design could make social play feel bureaucratic or imply a promise is mechanically binding.

5
Strategic continuity and recall provenance

5. Player Decision Spine + Restart-Proof Index

Description: Promote an actor’s exact accepted-action chain—decision receipt, accepted canonical event, and later consequence—into the primary private self-recall surface. Checkpoints retain only safe source locators, typed summaries, and audience scope; on recovery, each item is revalidated from durable authorized sources or omitted. Raw prompt, response, reasoning, and producer source-pointer material never crosses into the player prompt.

Axis
Strategic continuity and recall provenance
Basis
direct: accepted-action correlation already requires fresh decisionId and exact canonical linkage, while continuity capsules reject raw prompt/response/thinking fields and validate recovery state.
Rationale
Agents can remember “I voted X and it resolved as Y” without inventing a causal story from a stale strategy packet or unsafe trace.
Downsides
Only accepted actions link exactly; rejected, repaired, or fallback choices must remain explicitly unlinked rather than being retrofitted for prettier continuity.

88%

6
Shadow evaluation and rollout proof

6. Context Policy Trial

Description: Make the first delivery a deterministic paired replay harness, not live semantic retrieval. It produces today’s context and candidate RecallPlans for the same recorded game state, then evaluates required-fact coverage, prohibited-lane absence, evidence provenance, social-continuity fixtures, token/cache/latency deltas, and model fallback or accepted-action regressions. Only a policy that clears hard safety gates progresses to the existing bounded operator run.

Illustrative rollout gate: a token win never compensates for a truth or privacy miss.

Axis
Shadow evaluation and rollout proof
Basis
direct: the repo already distinguishes deterministic evidence from bounded real-model proof, accepted actions from fallbacks, and structural prompt telemetry from payload retention. external: retrieval evaluation needs precision, noise sensitivity, and faithfulness—not a single relevance score.
Rationale
It gives the team a way to reject “cheap but amnesiac” policies before they touch a paid run or silently degrade a watchable game.
Downsides
Requires a curated corpus of difficult social continuity and privacy cases; good fixtures take judgment and cannot be delegated to a generic benchmark.
